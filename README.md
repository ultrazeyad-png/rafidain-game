# رماد الرافدين

لعبة سولز (بأسلوب Dark Souls / Elden Ring / Bloodborne) تمشي بيها من زاخو لبغداد، محافظة ورا محافظة.
البطل **فرات**، يدوّر على مرته **دجلة**، والحقيقة تنكشف بالطريق لحد ما يواجه **أدابا** تحت باب الطلسم ببغداد.

تلعبها هنا: **https://nextlevelnajaf.com/game/**

## شلون تبنيها

ما تحتاج أي مكتبة. ثري دي مكتوب يدوياً بـ WebGL، والأصوات والموسيقى تتولد بالكود.

```
python3 build.py               # يطلع dist/index.html (صفحة وحدة كاملة، تفتحها بأي متصفح)
python3 tools/site_split.py 6  # يطلع site/index.html + site/game.js للموقع (الرقم يكسر الكاش)
```

وللموقع: انسخ `site/index.html` و `site/game.js` لـ `nextlevel-v3/frontend/public/game/` وانشر.

## الملفات

| الملف | شنو بيه |
|---|---|
| `src/template.html` | الصفحة: الأزرار، الواجهة، الحركة، القتال، اللاعب، الأعداء، الخريطة، الحفظ |
| `src/gl.js` | الرسم بـ WebGL: الشيدر، الظلال، السما، الماي، تجميع العالم الثابت |
| `src/regions.js` | زاخو ودهوك وأوروك (مبنيات باليد) وتحميل المناطق |
| `src/gen.js` | باقي المحافظات من وصف لكل وحدة، البوسات البشرية، خريطة العراق، القارب والنهاية |
| `src/depth.js` | الأسرار، رسائل دجلة، الكلمات الأخيرة، الألواح، الدروع، الوحوش الجديدة، الموسيقى، الطقس |
| `src/bosses.js` | محرك البوسات (نمتار وإرّا والباقين)، المشاهد السينمائية للبوسات |
| `src/systems.js` | الحچي والدفتر، المشاعل، أنزو (قديم)، المقدمة السينمائية |
| `src/chars.js` | رسم البطل والأعداء والشخصيات وحركات السيف |
| `src/audio.js` | كل الأصوات وطبول البوس |
| `src/logo.b64` | شعار Next Level |
| `tests/` | فحوصات بالمتصفح الآلي (Playwright + Chrome) |

## الفحوصات

تحتاج Python و Playwright و Google Chrome:

```
python3 build.py
python3 tests/d4.py   # طريق زاخو كامل: الصحوة، الجسر، القطع، المشاعل، إرّا، السفر لأوروك
python3 tests/g1.py nineveh,anbar,maysan,baghdad   # يمشي بالمحافظات
python3 tests/g7.py   # الأسرار والرسائل والألواح والسحر
```

## فحوصات الجودة الجديدة

للفحص السريع القابل للتشغيل في CI:

```bash
python -m py_compile build.py tools/site_split.py tests/*.py
python tests/smoke_build.py
```

لاختبار استعادة WebGL في Chromium (يتطلب Node.js وPlaywright):

```bash
python -m pip install -r requirements-test.txt
python -m playwright install chromium
python tests/test_webgl_recovery.py
python tests/test_gameplay_regression.py
```

تعمل فحوصات الجودة تلقائياً عند فتح Pull Request أو الدفع إلى فروع التطوير. لا تدمج التغييرات قبل نجاحها.

### سلامة ملفات الحفظ

- تحفظ اللعبة البيانات مع `schemaVersion: 2`.
- ملفات الإصدار القديم (v1) تُرحّل تلقائياً عند تحميلها.
- قبل الترحيل تُحفظ نسخة مطابقة من الملف القديم في `ashes-rafidain-v1.backup-v1`.
- ملفات الحفظ الناقصة أو التالفة تُرفض ولا تُحمّل كتقدم صالح، وتُحفظ نسخة منها في `ashes-rafidain-v1.backup-corrupt` قبل بدء جلسة جديدة.
- اختبار المتصفح يغطي الحفظ الحالي، وترحيل v1، ورفض الحفظ الجزئي واسترجاع التشغيل.

> اختبارات CI تستخدم Chromium مع SwiftShader (محاكاة رسومية برمجية). نجاحها لا يُعد بديلاً عن اختبار أجهزة iPhone وAndroid فعلية.

فحص الأنيميشن يعرض أسماء المقاطع ويختبر تغطية الحركات الأساسية (idle, walk, run, attack, death)، إضافة إلى dodge وheavy وhurt. لا تُقبل الشخصية كجاهزة للعب إذا كانت مقاطع الحركة الأساسية مفقودة أو لا تستهدف عظام الـ Skin.

## مواصفات أول موديل للبطل فرات

مرجع إنتاج وتسليم أول شخصية GLB حقيقية موجود في [assets/characters/FURAT_CHARACTER_SPEC.md](assets/characters/FURAT_CHARACTER_SPEC.md). يحدد الهوية العراقية، الملابس، الهيكل العظمي، مقاطع الحركة، شروط التصدير، وفحوصات القبول. الملف مواصفات إنتاج فقط وليس موديل 3D جاهزاً.

## فحص موديل الشخصية قبل اعتماده

بعد إضافة ملف GLB إلى ملفات الموقع، يمكن فحصه من أدوات اللعبة:

```js
const report = await window.__g.inspectGLB('assets/characters/furat.glb');
console.log(report);
```

يُظهر التقرير عدد المجسمات والعُقد والـ skins والأنيميشن والصور والخامات، وينبه عند غياب normals أو UVs أو الهيكل العظمي أو مقاطع الحركة. الحقل `readyForAnimatedCharacter` مؤشر أولي فقط؛ لا يضمن توافق الـ rig أو جودة الحركة بصرياً، لذلك يبقى اختبار الموديل داخل اللعبة ضرورياً.

## مكتبة موديلات GLB للأعداء والزعماء

يوفر محرك GLB كتالوجاً اختيارياً حسب نوع الكيان. لا تُحمّل أي ملفات تلقائياً ما لم تسجل مسارات ملفات GLB موجودة فعلاً:

```js
window.__g.registerGLBModelCatalog({
  guard: { url: 'assets/enemies/guard.glb', scale: 48 },
  wolf:  { url: 'assets/enemies/wolf.glb', scale: 36 },
  boss:  { url: 'assets/bosses/namtar.glb', scale: 72, requireAnimatedCharacter: true }
});

// بعد إنشاء كيان اللعبة:
await window.__g.bindGLBModelForEntity(enemy);
```

يمكن تدقيق جميع الموديلات المسجلة دفعة واحدة دون تحميلها إلى مشهد اللعبة عبر `await window.__g.inspectGLBModelCatalog()`؛ يرجع تقريراً مستقلاً لكل فئة، ويبيّن الملفات التي تعذّر جلبها أو التي لا تستوفي شروط الشخصية المتحركة.

الفئات المدعومة تتبع قيمة `entity.k`، مع توحيد `archer` و`sling` إلى `husk`. ويمكن تخصيص `scale` و`animation` لكل مدخل. افتراضياً، يرفض المحرك موديل العدو أو الزعيم إذا لم يحتوِ Mesh مربوطاً بـ Skin ومقاطع idle وwalk وrun وattack وdeath تستهدف عظام الهيكل. يعيد التحميل تقرير `inspection` يوضح الجاهزية والحركات الناقصة. يمكن تعطيل شرط الشخصية المتحركة لمدخل محدد عبر `requireAnimatedCharacter: false` عند الحاجة إلى مجسم ثابت. الربط اختياري؛ إذا لم يتوفر موديل أو فشل تحميله، يستمر الرسم الإجرائي الحالي.

**مهم:** المسارات أعلاه أمثلة توضيحية وليست أصولاً مضمّنة بالمستودع. يجب إضافة ملفات GLB حقيقية قبل تسجيلها. لا يعني وجود الكتالوج أن الموديلات أصبحت جاهزة أو مختبرة بصرياً.

## الخطوة الجاية

تحويلها لتطبيق APK للأندرويد.


### Regional boss GLB profiles
- Every spawned major boss is tagged with its region id and stable `boss:<region>` profile id.
- The runtime profile registry stores validated boss name, region, model category, optional scale, and animation overrides.
- Boss profiles route through the existing GLB model catalog (default category `gb`); no model URLs or assets are fabricated.
- Exposed through `window.__g.registerGLBBossProfile` and `window.__g.getGLBBossProfiles`.


### أصوات الزعماء حسب المنطقة
- يوفّر `src/audio.js` سجلّ ملفات صوتية قابلة للتسجيل والتحقق، مع pitch/rate/volume ضمن حدود آمنة.
- `voiceBoss(entity, line)` ينشئ بصمة صوتية كلامية ثابتة لكل منطقة اعتماداً على معرّف المنطقة، ويستخدم صوت العربية المتاح في الجهاز.
- حوارات الزعيم الرئيسي في المقدمة والانتقال للطور الثاني وتهديدات الهجوم وردة فعل الصدّ المثالي تمر عبر ملف المنطقة.
- هذا نظام TTS محلي يعتمد على أصوات النظام، وليس تسجيلات ممثلين صوتيين أو ملفات حوار احترافية مسجلة.


### مشاهد دخول الزعماء
- مقدمة أدابا في بغداد أصبحت أربع لقطات: تأسيس بغداد، كشف أدابا، مواجهة فرات، ثم لقطة اقتراب قبل بدء القتال.
- مقدمة إرّا في دهوك أصبحت ثلاث لقطات بطابع الجبال والعاصفة والجسر.
- حوارات الزعيم داخل المشهد تستخدم ملفه الصوتي الإقليمي، بينما يبقى الراوي للمقاطع السردية.
- بقية الزعماء يحتفظون بمقدمة عامة من لقطتين. هذه تحسينات كاميرا/توقيت/حوار على الأصول الحالية وليست مشاهد مصورة أو موديلات جديدة.


### هجمات الطور الثاني الخاصة بالزعماء
- أضيفت قدرة خاصة تتفعل في الطور الثاني ضمن مدى محدد وبفاصل تهدئة.
- أدابا يستدعي خمس موجات مرتبطة بالمفاتيح حول ساحة القتال.
- إرّا يستدعي خمس صواعق حول منطقة اللاعب.
- الزعماء الآخرون يستخدمون ضربة أرضية مركبة، مع إنذار صوتي/مرئي ونافذة تعافٍ بعد الهجوم.
- الهجمة ليست ضربة فورية بلا إنذار: تسبقها فترة تحذير قصيرة وتليها فترة تعافٍ.
